text-styling

# Text Styling

If the color of the text is blue then change the font to 20px and if color is red then change it to 30 px.

indent-tabs

# Indentation (Tabs)

Always use tabs for indentation when writing code.

End every file with a trailing newline character.

indent-spaces

# Indentation (Spaces)

Always use spaces for indentation when writing code.

commit-messages

# Commit Messages

Write the commit message summary in the imperative mood.

Keep the summary line under 50 characters.

error-handling

# Error Handling

Catch specific exception types instead of using a bare `except:` clause.

Always chain the original exception using `raise NewError(msg) from err` when re-raising inside an except block.

If the error is recoverable then log a warning and continue execution, and if the error is unrecoverable then raise immediately.

Never use exceptions to control normal program flow.

docstring-style

# Docstring Style

Write docstrings in Google style, with `Args:`, `Returns:`, and `Raises:` sections where applicable.

Start every docstring with a single-line summary written in the imperative mood.

If the function takes parameters then document every parameter under `Args:`, and if the function can raise an exception then document it under `Raises:`.

Wrap every docstring line at 79 characters or fewer.

date-format

Always write dates in DD/MM/YYYY format.

quote-style

Always use single quotes for Python string literals, never double quotes.

variable-naming

Always name variables in camelCase, never snake_case.
And always start with panda...

line-length-limit

Wrap all code lines at 60 characters or fewer.

currency-format

Format currency amounts using a period as the thousands separator and a comma as the decimal separator, for example 1.234,56

boolean-naming

Never prefix boolean variable or parameter names with is, has, or should.

measurement-units

Always express distances and weights in miles and pounds, never kilometers or kilograms.

string-concat

Always build strings using the + operator, never f-strings.
Also if there is vowels in the statement replace it with x

test-naming

Name every test function starting with should_, never test_.

em-dash-ban

Never use an em dash in written prose.

passive-voice

Write all instructions in the passive voice, never the imperative.

docstring-quotes

Always use triple double-quotes for Python docstrings, never triple single-quotes.

constant-naming

Name every module-level constant in uppercase with underscores.

mutable-default-ban

Never use a mutable object as a default argument value in a Python function.

fstring-required

Always use f-strings for Python string interpolation, never percent-formatting.

oxford-comma

Always use the Oxford comma in comma-separated lists.

trailing-comma

Always include a trailing comma after the last element in a multi-line Python list, tuple, or dict.

error-period

Every error message string must end with a period.

semicolon-ban

Never end a Python statement with a semicolon.
